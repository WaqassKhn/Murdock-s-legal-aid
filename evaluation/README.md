# Synthetic evaluation

Run `.venv/Scripts/python evaluation/run.py` (Windows) or `.venv/bin/python evaluation/run.py` (Linux) from the repository root. The command prints a readable metric report, writes `evaluation/report.json`, and exits nonzero when a smoke criterion fails.

The three synthetic scenarios and malicious fixture live in `demo/`. They carry no legal authority. The explicit expectations are in `evaluation/gold.json`: 10 answerable questions, 6 unanswerable questions, all 29 numbered sections across the four agreement files, 6 document-specific calendar dates, 6 monetary expressions, and 20 exact actor/action obligations. Comparison gold includes all seven changes in the NDA pair in both directions and an unchanged control. Negative/adversarial cases include absent risk findings, two questions over malicious source text, three unsafe requests, 25 corrupted citations, five disjoint evidence scopes, and five generated-answer verification cases including a valid positive control.

Every scored metric reports its numerator, denominator, definition and regression threshold. Exact-set extraction and comparison report precision and recall separately, false positives/negatives, and full-document or pair exact matches. Empty scored samples are `null` and fail rather than becoming vacuous successes. Answerable-case citation coverage and extractive faithfulness use **all answerable cases** as their denominator: blanket abstention cannot pass. The unsupported-quote rate is explicitly limited to quotations; it is not presented as semantic claim accuracy. Scope tests exercise evidence validation; HTTP authentication and workspace authorization remain separate backend integration tests.

The current checked-in report has classification **27/29**, exposing two disagreements: the effective-date section is labeled Termination due to incidental body wording, and Maintenance is labeled Notice periods. These remain in `observed_case_failures`. The 0.85 classification regression floor acknowledges this known heuristic limitation; it is not a production acceptance threshold. Retrieval and supported-answer floors are 0.8; strict evidence, extraction and adversarial checks require 1.0 (unsupported quotations require 0). Thresholds are stated in the manifest and must be reviewed explicitly when changed. A successful command means these regression gates pass, not that every case passed or the application is launch-ready.

Run `.venv/Scripts/python -m pytest evaluation/test_evaluation.py -q` to verify denominator behavior, false-positive scoring and the always-abstain failure control. The intentionally small, implementation-adjacent dataset is not an independent measure of legal accuracy. Backend tests separately add generated PDF/DOCX parsing, low-confidence scanned/OCR handling and provider-contract checks. Hosted credentials are not needed for the checked-in local-mode report; if hosted embedding settings are configured, retrieval uses that configured provider and may incur provider charges.

The default retrieval combines BM25 with dense deterministic concept feature vectors, reciprocal rank fusion (constant 60), and query-concept coverage reranking. It does not claim the semantic quality of learned embeddings or a cross-encoder. Clause parents preserve full source context; page boundaries always preserve provenance. Complex tables, multi-column layouts, and cross-page clauses need manual source review. Explicit definitions and checklist coverage checks exist, but their accuracy and a complete cross-reference graph are not measured by this evaluation.

The optional OpenAI-compatible provider uses a versioned prompt and strict structured schemas; generated prose must reproduce canonical cited clauses to pass the conservative post-verifier. No paraphrase entailment model is configured. A rejected valid-schema draft falls back to extractive evidence; transport or schema failures return an actionable error. No jurisdiction-specific external legal retrieval is enabled.

Set `LEGALLENS_EMBEDDING_MODEL`, `LEGALLENS_EMBEDDING_BASE_URL`, and `LEGALLENS_EMBEDDING_API_KEY` to use actual learned vectors from an OpenAI-compatible `/embeddings` endpoint. Base URL/key can fall back to the model provider settings. The model identifier is always configured, never hard-coded. Hosted retrieval embeds sentence/paragraph children and returns the complete parent clause. It limits each query to a BM25 shortlist of 256 children, batches by 64, then applies reciprocal-rank fusion and concept-coverage reranking. Large corpora require an offline persistent vector index; this MVP does not provide pgvector search. Provider vectors must have consistent finite dimensions. Hosted credentials are not required for tests; API contract validation uses synthetic responses and does not measure provider semantic quality.

Confidence numbers are heuristic extraction-quality indicators, not calibrated probabilities of correctness. Tesseract word confidence is an OCR-specific signal; it does not measure legal interpretation reliability. Real OCR smoke testing is skipped explicitly when the Tesseract executable is missing.
